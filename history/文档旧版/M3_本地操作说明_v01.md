# 项目 Cprime · M3 本地操作说明(平衡段 + SMD 生产段)

> 适用:你的 RTX 4070S + Amber 25(pmemd.cuda)。日期:2026-08-14。
> 所有路径均与你 GitHub 仓库(`amazingand/6VSB-simulation-archive`)的目录结构一致。
> 配套文档:《M3 模拟协议规划.md》(参数定义、云侧基准轨迹、决策表)。

---

## 0. 两段式流程一句话

```text
run_equil.sh(平衡,到 EQ4 停) ──▶ 同步 GitHub + 云侧核验(能量轨迹对齐) ──▶ run_smd.sh(SMD 生产)
```

**SMD 生产绝不跳过快验直接开跑。** 平衡段是你本地先跑,核验由云侧完成。

## 1. 目录布局(与 GitHub 一致)

```text
6VSB-simulation-history/                       ← 仓库根
└── simulations/
    └── construct-X/
        ├── cleaved/
        │   ├── construct_X_cleaved.pdb        ← GitHub 已有
        │   ├── construct_X_cleaved.tgz        ← GitHub 已有(LFS)
        │   └── amber/                         ← tgz 解压出的 CHARMM-GUI AMBER 产物
        │       ├── step3_input.parm7          ← 拓扑(CHARMM-GUI 提供)
        │       ├── step3_input.rst7           ← 坐标(CHARMM-GUI 提供)
        │       ├── dihe.restraint             ← 糖二面角约束(CHARMM-GUI 提供)
        │       ├── step4.0_minimization.mdin  ← CHARMM-GUI 自带,不动
        │       ├── README / sysinfo.dat ...
        │       ├── align_min.mdin             ← 以下均为 M3 协议文件(本套件)
        │       ├── eq1_nvt.mdin … eq4_npt.mdin
        │       ├── smd_pull.mdin + smd.RST
        │       ├── run_equil.sh  run_smd.sh  analyze_smd.py
        │       └── …(运行产物: align_min.rst7, eq4_npt.rst7, …)
        └── uncleaved/
            ├── construct_X_uncleaved.pdb
            ├── construct_X_uncleaved.tgz
            └── amber/                          ← 同上, 但用 uncleaved 套 mdin
```

**要点**:
- 脚本**在 `amber/` 目录里运行**(它从当前目录找 `step3_input.parm7` / `step3_input.rst7` / `dihe.restraint`),不要在别的目录执行;
- cleaved / uncleaved 各用**各自的一套** mdin(`M3_协议文件/cleaved/` 与 `M3_协议文件/uncleaved/`),两套的差异是 posres 段与 SMD 约束原子编号,不可混用;
- 运行产物(align_min.*、eq*.rst7/nc 等)会写进同一个 `amber/` 目录,建议跑完一个体系再跑另一个,避免同名覆盖。

## 2. 环境与前置检查

```bash
# Amber 25 环境(你的机器)
cd ~/6VSB-simulation-history/simulations/construct-X/cleaved/amber
```

### 2.1 引擎选择(WSL2 注意)

脚本**不会自动运行 GPU 版 pmemd.cuda**。引擎按以下优先级确定:

| 优先级 | 方式 | 示例 |
|---|---|---|
| 1 | 命令行 `--engine=` | `bash run_equil.sh cleaved --engine=pmemd.cuda` |
| 2 | 环境变量 `PMEMD_ENGINE` | `export PMEMD_ENGINE=pmemd.cuda` |
| 3 | 自动探测 | 默认逻辑,见下 |

**自动探测在 WSL 环境默认回退 CPU 版 `pmemd`**(若检测到 `pmemd.cuda` 会打印警告并提示)。原因:**WSL2 下若 NVIDIA WSL 驱动未配置好,直接运行 `pmemd.cuda` 会强制退出整个 WSL**(本地 4070S 需先在 Windows 侧装好 NVIDIA WSL 驱动并确认 `nvidia-smi` 在 WSL 里能出卡)。确认 GPU 可用后,再显式 `--engine=pmemd.cuda` 启用加速。

> 判断是否 WSL:脚本读取 `/proc/sys/kernel/osrelease` 是否含 `microsoft`。原生 Linux 不受影响,自动探测会正常选 `pmemd.cuda`。

```bash
# 确认 GPU 可用(WSL2 里能出卡才用 pmemd.cuda)
nvidia-smi
```

前置文件核对(`amber/` 目录内必须有):
| 文件 | 来源 | 作用 |
|---|---|---|
| `step3_input.parm7` | CHARMM-GUI 输出 | 拓扑 |
| `step3_input.rst7` | CHARMM-GUI 输出 | 初始坐标 |
| `dihe.restraint` | CHARMM-GUI 输出 | 糖二面角约束(脚本自动转成 dihe_FC1.rest) |
| `align_min.mdin` | M3 套件 cleaved/ | 对齐极小化 |
| `eq1_nvt.mdin`–`eq4_npt.mdin` | M3 套件 cleaved/ | 阶梯平衡 |
| `smd_pull.mdin` + `smd.RST` | M3 套件 cleaved/ | SMD(第二步才用) |

> uncleaved 同理, 但 mdin 来自 `M3_协议文件/uncleaved/`。

## 3. 第一步:平衡段(run_equil.sh)

```bash
# 在 cleaved 的 amber/ 目录里
bash /绝对路径/M3_协议文件/run_equil.sh cleaved
# 或把脚本复制到当前目录后:
bash run_equil.sh cleaved
```

脚本依次执行并输出进度:
```text
[1/5] 对齐极小化 (align_min, 5000 步)   → align_min.rst7 + align_min.mdout
[2/5] EQ1 NVT 升温 (100 ps)              → eq1_nvt.rst7/.nc
[3/5] EQ2 NPT (200 ps)                   → eq2_npt.rst7/.nc
[4/5] EQ3 NPT (200 ps)                   → eq3_npt.rst7/.nc
[5/5] EQ4 NPT 自由平衡 (500 ps)          → eq4_npt.rst7/.nc  ← SMD 生产起点
```

- 想顺带跑 **EQ5 稳定性检验**(对照用):加 `--eq5`
  ```bash
  bash run_equil.sh cleaved --eq5
  ```
- 预估时长(4070S):对齐极小化 5000 步约 **1–2 分钟**;EQ1–EQ4 共 1 ns,约 **0.5–1 小时**(看你 PME 性能)。
- **EQ 中途断了?** 脚本是线性的,已完成的阶段产物在,重跑会从头再来——不想重跑就只补跑中断后的阶段(见 §6 常见问题)。

## 4. 第二步:同步 GitHub + 云侧核验

平衡段跑完后:

```bash
# 在仓库根目录
cd ~/6VSB-simulation-archive
git add simulations/construct-X/cleaved/amber/align_min.mdout
git add simulations/construct-X/cleaved/amber/align_min.rst7
git commit -m "C' cleaved: align_min 完成(5000 步), 待云侧核验"
git push
```

我拉取后做 **能量轨迹对齐核验**:
- 你 mdout 里**前 100 步能量轨迹**(步 1,10,20,…,100)应落在云侧基准曲线附近(cleaved:7.67E12 → −9.65E5;uncleaved:−9.08E5 → −9.69E5,完整表见《M3 模拟协议规划.md》§5);
- 最终能量应落在 **−9.8E5 ~ −9.9E5**(kcal/mol)区间;
- 趋势与量级一致即核验通过 → 我会确认"分界点 OK,可以跑 SMD"。

> 若你不想传坐标,只推 `align_min.mdout` 也行(核验只看能量轨迹)。rst7 同步上传是为了一致性存档。

## 5. 第三步:SMD 生产(run_smd.sh)

**仅在云侧核验通过后执行。**

```bash
# 仍在 amber/ 目录
bash run_smd.sh cleaved             # 5 Å/ns 初筛 (5.24 ns) ← 先跑这个
bash run_smd.sh cleaved --smd-speed 1   # 1 Å/ns 定量 (26.2 ns, 核验初筛结果后)
```

- 从 `eq4_npt.rst7` 接续,自动生成对应拉速的 mdin(1 Å/ns 版自动写 `smd_pull_1ans.mdin`);
- 产物:`smd_pull.nc`(轨迹)+ `smd.out`(DUMPAVE 拉力/功,每 1000 步);
- 时长(4070S):5 Å/ns 版约 **0.5–1 h**;1 Å/ns 版约 **2.5–5 h**,建议挂后台(`nohup … &` 或 screen/tmux);
- **每 1 ns 可先看一眼 `smd.out` 的力曲线,确认解离进行中**(力不应一直为零或爆表)。

## 6. 分析

```bash
python analyze_smd.py smd.out --plot
```

输出:4 幅曲线(力–时间、力–位移、功–时间、功–位移)+ 数据表 `smd_curves.dat`,并打印解离完成距离、峰值力、累计做功。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 用 sander 试跑报 `Error decoding variable from: Protein` | 正常——这是 **sander 的已知缺陷**(CHARMM-GUI README 明说:sander 需移除 `&end`)。本套件 mdin 是 **pmemd/pmemd.cuda 标准格式(带 `&end` 约束块终止符)**,请用 pmemd.cuda 或 pmemd 运行;云侧基准是用不带 `&end` 的 sander 版生成的,能量轨迹与本格式一致(`&end` 是语法终止符,不影响数值) |
| 脚本在 WSL2 里自动用了 CPU 版 pmemd | **正常设计**,避免 GPU 二进制崩溃整个 WSL;先用 `nvidia-smi` 确认 GPU,可用后加 `--engine=pmemd.cuda` |
| 加了 `--engine=pmemd.cuda` 后 WSL 仍崩 | NVIDIA WSL 驱动没配好:在 Windows 侧装 NVIDIA WSL 驱动,或在 WSL 里装 `cuda-toolkit`/`nvidia-driver`;未配好前用 CPU 版(pmemd/sander) |
| `--engine=nonexist` | 脚本会明确报"未找到引擎"并退出,不会静默回退 |
| `缺 step3_input.parm7` | 你在错误的目录跑了——脚本必须在 `amber/` 目录内执行 |
| 极小化报错/能量巨大 | cleaved 体系初始能量 7.67E12 是**正常**的(S2′ 切割末端原子重叠),几百步内会降到 −9E5;若跑完仍 >1E10,停下检查 |
| EQ1 报 "NTB set but no NTP" | mdin 被改坏——重拷一份套件 mdin |
| `align_min.mdout` 里能量 vs 云侧差最后 1–2 位小数 | 正常:sander 与 pmemd.cuda 浮点实现略异,看趋势与前 5–6 位有效数字 |
| 两个体系输出互相覆盖 | 分开目录跑,或跑完一个再跑另一个 |
| 想从头重跑平衡 | 删掉 amber/ 里旧的 align_min/eq*.rst7/nc/mdout 再跑(保留原始 step3_input.*) |

## 8. 参数速查(已确认,勿改动)

| 参数 | 值 |
|---|---|
| 反应坐标 | S1尾 144 Cα ↔ S2头 200 Cα 的 COM 距离 |
| 范围 | 28.80 Å → 55 Å(位移 26.2 Å) |
| 拉速 | 5 Å/ns(初筛)→ 1 Å/ns(定量) |
| 力常数 rk2 | 7.2 kcal/mol/Å² |
| 温度/压力 | 310.15 K / 1 bar(NPT,Langevin γ=1.0) |
| SMD posres | 只锚 S2 头(cleaved:`RES 1 151 152 371`;uncleaved:`RES 1 371`) |
| 平衡 | EQ1 NVT 100ps → EQ2/EQ3 NPT 200ps → EQ4 NPT 500ps(糖 dihe 全程) |
