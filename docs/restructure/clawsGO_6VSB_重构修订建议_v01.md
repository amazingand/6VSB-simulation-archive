# 对 clawsGO 的 6VSB 文件结构重构修订建议

请基于当前《重构后效果图 v01》继续修订，保留现有“研究问题 → 体系 → SMD运行 → 分析 → 对比 → 论文”的论文逻辑主轴。当前方案总体方向正确，但正式执行迁移前需要按以下规则调整。

## 1. 顶层项目文件不做版本号管理

以下文件属于项目持续维护的顶层状态文件：

- `README.md`
- `NODES.md`
- `PROGRESS.md`
- 各层 `PROGRESS.md`
- 各层 `USAGE.md`

这些文件通过持续追加和更新内容反映当前项目状态，不额外增加 `_vNN` 标签。

`vNN` 迭代标签主要用于具有明确科研版本意义的脚本、输入、数据、报告、图表等产物。

## 2. 保留“产出—说明”对应关系，并提高 USAGE 的粒度

当前为各阶段设置 `PROGRESS.md` 和 `USAGE.md` 的方向保留。

其中：

- `PROGRESS.md`：负责该阶段整体进展、完成内容、当前状态、问题和下一步；
- `USAGE.md`：负责说明该目录中的具体科研产物如何使用。

对于包含多个独立脚本或工具的目录，`USAGE.md` 必须按文件分别建立条目，例如：

```text
## analyze_smd_contacts_v02.py
用途
适用体系
输入
输出
调用方式
限制
已知问题

## run_replica_v01.sh
...
```

不得只写笼统的目录级说明。

## 3. 取消所有 cleaved / uncleaved 共享层

这是本次修订的核心要求。

此前已经发生过因 cleaved 与 uncleaved 两套体系混淆，导致 `analyze_smd_contacts.py` 对 uncleaved 数据处理错误并返修的问题。

因此今后不再以“内容相同”为理由合并任何与体系相关的：

- Python 脚本；
- Shell 脚本；
- mdin；
- 配置文件；
- 输入文件；
- 日志；
- 分析文件；
- 结果文件。

当前效果图中的 `03_SMD运行/共享/` 和 `04_分析/共享/` 应取消。

改为严格双体系镜像结构，例如：

```text
03_SMD运行/
├── cleaved/
│   ├── run_equil_cleaved_...
│   ├── run_smd_cleaved_...
│   ├── smd_pull_cleaved_...
│   └── USAGE.md
│
└── uncleaved/
    ├── run_equil_uncleaved_...
    ├── run_smd_uncleaved_...
    ├── smd_pull_uncleaved_...
    └── USAGE.md
```

以及：

```text
04_分析/
├── cleaved/
│   ├── analyze_smd_cleaved_...
│   ├── analyze_smd_contacts_cleaved_...
│   ├── ...
│   └── USAGE.md
│
└── uncleaved/
    ├── analyze_smd_uncleaved_...
    ├── analyze_smd_contacts_uncleaved_...
    ├── ...
    └── USAGE.md
```

即使两个文件当前字节级完全相同，也分别保留。

从此遵循：

> `01–04` 阶段原则上不存在双体系共享执行文件。

### 唯一允许汇合的位置

`05_对比/` 保持为唯一合法双系统节点。

只有进入明确的 cleaved vs uncleaved 对比分析后，才允许同时读取两个体系的数据。

因此整体边界为：

```text
CLEAVED ───────────────┐
                       │
01–04 全程严格隔离      ├──→ 05_对比
                       │
UNCLEAVED ─────────────┘
```

## 4. 历史交付文件完全移出工作体系

现有 `cleaved.tgz`、`uncleaved.tgz`、旧 SMD 交付包等历史交付物继续保留，但：

- 不再移动；
- 不再重命名；
- 不再更新；
- 不参与当前论文逻辑目录；
- 不参与当前科研工作流；
- 不参与迁移包生成。

它们仅作为只读历史证据存在。

当前 v01 将其放入 `01_研究问题/历史交付/` 的方案取消。

历史交付区视为：

```text
当前工作体系之外的只读溯源区
```

不得再参与后续重构。

## 5. 迁移包规则同步修改

`pack_migration.sh` 可以继续保留作为按需工具，但生成迁移包时只打包当前有效工作体系。

不得包括历史交付区。

仍然遵循：

> 正常情况下不产生迁移包；只有用户明确提出迁移要求后才生成。

## 6. 正式执行前的最终结构原则

本次重构最终应遵循：

```text
论文逻辑主轴
+
cleaved / uncleaved 从体系到分析阶段完全物理隔离
+
科研产物使用 vNN 迭代标签追溯
+
PROGRESS 记录阶段进程
+
USAGE 逐项解释重要产物
+
05_对比作为唯一双体系汇合节点
+
历史交付区永久只读并排除在工作体系和迁移包之外
```

请据此更新重构效果图，在再次确认之前仍不要执行实际移动、删除或重命名。
