# 项目 Cprime · M3 本地操作说明(平衡段 + SMD 生产段)

> 适用:你的 RTX 4070S + Amber 25(pmemd.cuda)。**版本:2026-08-15(P4.1 部署单元)**。
> 所有路径均与你 GitHub 仓库(`amazingand/6VSB-simulation-archive`)的目录结构一致。
> 配套文档:`docs/M3_模拟协议规划_v01.md`(参数定义、云侧基准轨迹)、
> `docs/M3_SMD初筛核验报告_v02.md`(初筛核验 + 定量方案)。
> v01(旧命名 `run_smd.sh`/`smd.RST` 时代)已归档 `archive/文档旧版/`。

---

## 0. 两段式流程一句话

```text
run_equil.sh(平衡,到 EQ4 停) ──▶ 同步 GitHub + 云侧核验(能量轨迹对齐) ──▶ run_smd_{cleaved,uncleaved}.sh(SMD 生产)
```

**SMD 生产绝不跳过快验直接开跑。** 平衡段是你本地先跑,核验由云侧完成。

## 1. 目录布局(与 GitHub 一致)

```text
6VSB-simulation-archive/                       ← 仓库根
└── simulations/
    └── construct-X/
        ├── cleaved/
        │   ├── construct_X_cleaved.pdb        ← GitHub 已有
        │   ├── construct_X_cleaved.tgz        ← GitHub 已有(LFS)
        │   └── amber/                         ← tgz 解压出的 CHARMM-GUI AMBER 产物
        │       ├── step3_input.parm7          ← 拓扑(CHARMM-GUI 提供)
        │       ├── step3_input.rst7           ← 坐标(CHARMM-GUI 提供)
        │       ├── dihe.restraint             ← 糖二面角约束(CHARMM-GUI 提供)
        │       ├── step4.0_minimization.mdin  ← CHARMM-GUI 自带,不动
        │       ├── README / sysinfo.dat ...
        │       ├── align_min.mdin             ← 以下均为 M3 部署单元(P4.1)
        │       ├── eq1_nvt.mdin … eq4_npt.mdin
        │       ├── smd_pull_cleaved.mdin      ← SMD mdin 模板
        │       ├── smd_cleaved.RST            ← 反应坐标 R0=28.28 → RF=55.0
        │       ├── run_equil.sh  run_smd_cleaved.sh  analyze_smd.py
        │       └── …(运行产物: align_min.rst7, eq4_npt.rst7, smd_chunkNN.*, …)
        └── uncleaved/
            ├── construct_X_uncleaved.pdb
            ├── construct_X_uncleaved.tgz
            └── amber/                          ← 同上, 用 uncleaved 套件(smd_uncleaved.RST 等)
```

**要点**:
- 脚本**在 `amber/` 目录里运行**(它从当前目录找 `step3_input.parm7` / `step3_input.rst7` / `dihe.restraint`),不要在别的目录执行;
- cleaved / uncleaved 各用**各自的一套**部署单元(`protocols/construct-X/cleaved/` 与
  `protocols/construct-X/uncleaved/`),两套的差异是 R0(28.28 / 31.27)、posres 段与
  SMD 约束原子编号,**不可混用**;
- **命名纪律(P4.1)**:RST 统一叫 `smd_cleaved.RST` / `smd_uncleaved.RST`,脚本与 mdin
  模板全部对齐该名——改文件名必须连脚本引用一起改,否则前置检查会失败;
- 运行产物(align_min.*、eq*.rst7/nc、smd_chunkNN.*)会写进同一个 `amber/` 目录,建议跑完一个体系再跑另一个,避免同名覆盖。

## 2. 环境与前置检查

```bash
# Amber 25 环境(你的机器)
cd ~/6VSB-simulation-archive/simulations/construct-X/cleaved/amber
```

### 2.1 引擎选择(WSL2 注意)

脚本**不会自动运行 GPU 版 pmemd.cuda**。引擎按以下优先级确定:

| 优先级 | 方式 | 示例 |
|---|---|---|
| 1 | 命令行 `--engine=` | `bash run_smd_cleaved.sh --engine=pmemd.cuda` |
| 2 | 环境变量 `PMEMD_ENGINE` | `export PMEMD_ENGINE=pmemd.cuda` |
| 3 | 自动探测 | 默认逻辑,见下 |

**自动探测在 WSL 环境默认回退 CPU 版 `pmemd`**(若检测到 `pmemd.cuda` 会打印警告并提示)。原因:**WSL2 下若 NVIDIA WSL 驱动未配置好,直接运行 `pmemd.cuda` 会强制退出整个 WSL**(本地 4070S 需先在 Windows 侧装好 NVIDIA WSL 驱动并确认 `nvidia-smi` 在 WSL 里能出卡)。确认 GPU 可用后,再显式 `--engine=pmemd.cuda` 启用加速。

> 判断是否 WSL:脚本读取 `/proc/sys/kernel/osrelease` 是否含 `microsoft`。原生 Linux 不受影响,自动探测会正常选 `pmemd.cuda`。

```bash
# 确认 GPU 可用(WSL2 里能出卡才用 pmemd.cuda)
nvidia-smi
```

前置文件核对(`amber/` 目录内必须有):
| 文件 | 来源 | 作用 |
|---|---|---|
| `step3_input.parm7` | CHARMM-GUI 输出 | 拓扑 |
| `step3_input.rst7` | CHARMM-GUI 输出 | 初始坐标 |
| `dihe.restraint` | CHARMM-GUI 输出 | 糖二面角约束(脚本自动转成 dihe_FC1.rest) |
| `align_min.mdin` | 部署单元 cleaved/ | 对齐极小化 |
| `eq1_nvt.mdin`–`eq4_npt.mdin` | 部署单元 cleaved/ | 阶梯平衡 |
| `smd_pull_cleaved.mdin` + `smd_cleaved.RST` | 部署单元 cleaved/ | SMD(第二步才用) |

> uncleaved 同理, 部署单元来自 `protocols/construct-X/uncleaved/`(文件名用 `smd_uncleaved.*`)。

## 3. 第一步:平衡段(run_equil.sh)

```bash
# 在 cleaved 的 amber/ 目录里
bash /绝对路径/protocols/construct-X/cleaved/run_equil.sh
# 或把脚本复制到当前目录后:
bash run_equil.sh
```

> 注意:run_equil.sh 在当前目录运行(读当前目录的 mdin),无体系参数。cleaved 与
> uncleaved 各自复制到各自的 amber/ 目录执行。

脚本依次执行并输出进度:
```text
[1/5] 对齐极小化 (align_min, 5000 步)   → align_min.rst7 + align_min.mdout
[2/5] EQ1 NVT 升温 (100 ps)              → eq1_nvt.rst7/.nc
[3/5] EQ2 NPT (200 ps)                   → eq2_npt.rst7/.nc
[4/5] EQ3 NPT (200 ps)                   → eq3_npt.rst7/.nc
[5/5] EQ4 NPT 自由平衡 (500 ps)          → eq4_npt.rst7/.nc  ← SMD 生产起点
```

- 想顺带跑 **EQ5 稳定性检验**(对照用):加 `--eq5`
  ```bash
  bash run_equil.sh --eq5
  ```
- 预估时长(4070S):对齐极小化 5000 步约 **1–2 分钟**;EQ1–EQ4 共 1 ns,约 **0.5–1 小时**(看你 PME 性能)。
- **EQ 中途断了?** 脚本是线性的,已完成的阶段产物在,重跑会从头再来——不想重跑就只补跑中断后的阶段(见 §7 常见问题)。

## 4. 第二步:同步 GitHub + 云侧核验

平衡段跑完后:

```bash
# 在仓库根目录
cd ~/6VSB-simulation-archive
git add simulations/construct-X/cleaved/amber/align_min.mdout
git add simulations/construct-X/cleaved/amber/align_min.rst7
git commit -m "C' cleaved: align_min 完成(5000 步), 待云侧核验"
git push
```

我拉取后做 **能量轨迹对齐核验**:
- 你 mdout 里**前 100 步能量轨迹**(步 1,10,20,…,100)应落在云侧基准曲线附近(cleaved:7.67E12 → −9.65E5;uncleaved:−9.08E5 → −9.69E5,完整表见《M3 模拟协议规划_v01》§5);
- 最终能量应落在 **−9.8E5 ~ −9.9E5**(kcal/mol)区间;
- 趋势与量级一致即核验通过 → 我会确认"分界点 OK,可以跑 SMD"。

> 若你不想传坐标,只推 `align_min.mdout` 也行(核验只看能量轨迹)。rst7 同步上传是为了一致性存档。

## 5. 第三步:SMD 生产(run_smd_cleaved.sh)

**仅在云侧核验通过后执行。** 分片可重启:每段 1 ns,段间自动接续;断点续跑、换参数
自动重跑旧段,**无需手动清理**。

```bash
# 仍在 amber/ 目录(cleaved)
nohup bash run_smd_cleaved.sh --smd-speed 1 --engine=pmemd.cuda > smd_quant.log 2>&1 &
```

- 初筛(核验用, 非论文证据)用 `--smd-speed 5`;**定量用 `--smd-speed 1`**;
- **R0/RF 从 `smd_cleaved.RST` 读**(r2=起点, r4=终点),改它就改全局,脚本自动重算段数;
- 定量参数:cleaved **R0=28.28 → 55.0 Å, 1 Å/ns, 26.72 ns, 27 段**;
  uncleaved **R0=31.27 → 55.0 Å, 1 Å/ns, 23.73 ns, 24 段**;
- 产物:`smd_chunkNN.out/.mdout/.rst7`(每段)+ 跑完合并 `smd.out`(DUMPAVE 拉力/功);
- 时长(4070S):初筛 5 Å/ns 约 **1–1.5 h**(6 段);定量 1 Å/ns 约 **5–8 h**,务必挂后台
  (`nohup … &` 或 screen/tmux),跑完再启 uncleaved;
- 想中途看进度:`tail -f smd_quant.log`,或看已完成的 `smd_chunk*.out`。

## 6. 分析

```bash
python analyze_smd.py smd.out --speed 1 --plot
```

输出:4 幅曲线(力–时间、力–位移、功–时间、功–位移)+ 数据表,并打印解离完成距离、
峰值力、累计做功。初筛数据用 `--speed 5` 重画即可。
跑完推 GitHub(`smd.out` + 分片 `.out`),云侧复核力-位移曲线与功后写核验报告。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 用 sander 试跑报 `Error decoding variable from: Protein` | 正常——这是 **sander 的已知缺陷**(CHARMM-GUI README 明说:sander 需移除 `&end`)。本套件 mdin 是 **pmemd/pmemd.cuda 标准格式(带 `&end` 约束块终止符)**,请用 pmemd.cuda 或 pmemd 运行;云侧基准是用不带 `&end` 的 sander 版生成的,能量轨迹与本格式一致(`&end` 是语法终止符,不影响数值) |
| 脚本报"缺 smd_cleaved.RST" | 你把 RST 改名了但脚本没同步——P4.1 要求脚本引用与 RST 文件名一致,改一个必须改另一个 |
| 脚本显示"拉速 5 Å/ns"但你想跑定量 | 命令里**漏了 `--smd-speed 1`**(默认 5)。正确:`bash run_smd_cleaved.sh --smd-speed 1 --engine=pmemd.cuda` |
| 脚本在 WSL2 里自动用了 CPU 版 pmemd | **正常设计**,避免 GPU 二进制崩溃整个 WSL;先用 `nvidia-smi` 确认 GPU,可用后加 `--engine=pmemd.cuda` |
| 加了 `--engine=pmemd.cuda` 后 WSL 仍崩 | NVIDIA WSL 驱动没配好:在 Windows 侧装 NVIDIA WSL 驱动,或在 WSL 里装 `cuda-toolkit`/`nvidia-driver`;未配好前用 CPU 版(pmemd/sander) |
| `--engine=nonexist` | 脚本会明确报"未找到引擎"并退出,不会静默回退 |
| `缺 step3_input.parm7` | 你在错误的目录跑了——脚本必须在 `amber/` 目录内执行 |
| 极小化报错/能量巨大 | cleaved 体系初始能量 7.67E12 是**正常**的(S2′ 切割末端原子重叠),几百步内会降到 −9E5;若跑完仍 >1E10,停下检查 |
| EQ1 报 "NTB set but no NTP" | mdin 被改坏——重拷一份部署单元 mdin |
| `align_min.mdout` 里能量 vs 云侧差最后 1–2 位小数 | 正常:sander 与 pmemd.cuda 浮点实现略异,看趋势与前 5–6 位有效数字 |
| 某段被杀(NSTEP < 500000 且无 `Final Performance Info:`) | 重跑脚本自动删除该段、从上一完整段重跑,无需手动清理 |
| 两个体系输出互相覆盖 | 分开目录跑,或跑完一个再跑另一个 |
| 想从头重跑平衡 | 删掉 amber/ 里旧的 align_min/eq*.rst7/nc/mdout 再跑(保留原始 step3_input.*) |

## 8. 参数速查(已确认,勿改动)

| 参数 | cleaved | uncleaved |
|---|---|---|
| 反应坐标 | S1尾 144 Cα ↔ S2头 200 Cα 的 COM 距离 | 同左 |
| R0(eq4 实测平衡距离) | **28.28 Å** | **31.27 Å** |
| RF | 55.0 Å | 55.0 Å |
| 拉速 | 初筛 5 Å/ns → **定量 1 Å/ns**(证据) | 同左 |
| 定量时长 / 分片 | 26.72 ns / 27 段 | 23.73 ns / 24 段 |
| 力常数 rk2 | 7.2 kcal/mol/Å² | 7.2 kcal/mol/Å² |
| 温度/压力 | 310.15 K / 1 bar(NPT, Langevin γ=1.0) | 同左 |
| SMD posres | 只锚 S2 头(`RES 1 151 152 371`) | 只锚 S2 头(`RES 1 371`) |
| 平衡 | EQ1 NVT 100ps → EQ2/EQ3 NPT 200ps → EQ4 NPT 500ps(糖 dihe 全程) | 同左 |
